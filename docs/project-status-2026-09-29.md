## 本轮已处理

- 历史记录的页面结构保存现在接受前端和生成链路已经支持的 `infographic` 页面类型。
- 页面结构保存拒绝布尔值冒充页码索引，并保留 `cover`、`content`、`summary` 的原有行为。
- 下载对话框测试只检查“图片版本”选择框，不会因为“保存方式”新增目录/ZIP 选项而误报。
- 设置、提示词管理、参考素材和管理员页面改为路由级按需加载；工作台路由及路由守卫保持不变。
- pnpm 构建依赖白名单迁移到 `frontend/pnpm-workspace.yaml`，不再依赖已被当前 pnpm 忽略的 `package.json.pnpm` 字段。
- 平台风险表达规则已接入统一生成上下文，覆盖自动、小红书、抖音、公众号和通用多平台，以及大纲、文案、图片三个阶段。
- 规则只作为提示词约束，明确禁止谐音/拆字/特殊字符规避，也明确生成完成后不机械替换、删词或重写正文。

- 前端完整测试：59 个测试文件、562 个测试全部通过。
- 前端类型检查、测试类型检查和生产构建均通过；构建产物包含设置、提示词管理、参考素材和管理员页面的独立 chunk。

- `docker compose config --quiet` 使用临时配置通过，说明 Compose 配置可解析。
- 正式部署启动器包含生产密钥、管理员密码、Host、DEBUG 和配置文件检查。

## 有限验证

- 已对首页做过桌面 1280x720 和移动 390x844 的静态/交互预览，未发现横向溢出；尚未覆盖工作台生成、历史详情、图片后处理、设置和管理员页面的完整浏览器流程。
- 未调用真实付费模型，也未把第三方服务商凭据当作测试前提。

## 当前环境无法验证

- Docker Desktop Linux 引擎当前不可用：Docker 客户端存在，但 `dockerDesktopLinuxEngine` 管道不可连接。因此镜像构建、容器启动、worker 联动和 Linux 文件权限尚未实测。
- 生产 HTTPS、反向代理、真实多进程部署和真实模型请求不等同于本地测试通过。

## 仍需后续处理

- 平台表达风险提示词：已完成第一版保守规则并接入提示词。它不是实时或完整的官方违禁词库，也不保证任何平台审核通过；后续只需根据明确的新规则增量维护并补测试。
- 稳定页面 ID：当前结构编辑采用确认后清理旧图片、任务和候选结果的保护策略，尚未迁移到跨设备稳定 ID。
- 跨设备草稿的版本冲突：除结构变更外，普通保存仍没有统一的乐观版本号校验。
- 多 worker 下的取消与进度一致性：当前部署启动器仍按单 Gunicorn 进程、线程并发的约束运行，不能宣称已完成持久化取消架构。
- 需要在 Docker 引擎恢复后，于独立空数据目录完成 build/up、登录、迁移、worker、样图和静态文件验收。

## 结论

核心开发链路和平台风险提示词已经可以继续迭代，但项目还不能称为“所有功能、所有平台和生产部署均已完成验证”。共享 Skill 可以在本轮提示词功能验收后继续生成，同时保留 Docker、真实服务商和完整浏览器流程的未验证边界。
