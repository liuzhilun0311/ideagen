# 多平台获客内容推荐设计

## 1. 背景与目标

当前项目已经具备图片页面布局、图片风格、文案结构和比例选择能力，但推荐主要围绕“主题”进行，缺少发布平台和获客目标维度。对于小红书、抖音、公众号等平台，同一个主题需要不同的内容节奏、版式密度、图片比例和行动引导。

本功能的目标是增加一层可解释的“平台 × 获客目标 × 内容结构 × 视觉风格”推荐能力：

- 默认自动推荐，用户可以手动指定平台和目标。
- 保留现有布局、风格和历史记录的兼容性。
- 用户手动选择始终优先于系统推荐。
- 让样图、名称和说明能够直接帮助用户理解差异。
- 生成后检查文案与图片页面是否表达同一组内容。

## 2. 范围

### 2.1 本期范围

- 大纲创作参数增加发布平台和获客目标。
- 扩展页面布局目录，覆盖获客型内容结构。
- 扩展图片风格目录，覆盖商业、UGC、产品和视频内容场景。
- 为布局和风格增加适用平台、目标、比例、文字密度和样图元数据。
- 扩展推荐协议，返回平台、目标、布局、风格、比例、结构和推荐理由。
- 增加本地规则兜底，模型未返回推荐或返回无效值时仍能生成。
- 在结果页增加文案与图片的一致性检查结果。
- 支持样图点击放大，并对无样图项提供明确的占位状态。

### 2.2 不在本期范围

- 不拆分为三套完全独立的小红书、抖音、公众号生成系统。
- 不改变用户已经明确选择的模型、布局、风格、比例和输出格式。
- 不自动改写用户正文中的事实、数据或产品信息。
- 不要求历史记录重新生成或迁移。

## 3. 用户入口

在大纲创作参数中增加：

| 参数 | 默认值 | 选项 |
| --- | --- | --- |
| 发布平台 | 自动推荐 | 自动推荐、小红书、抖音、公众号、通用多平台 |
| 获客目标 | 自动推荐 | 自动推荐、涨粉关注、产品种草、私信咨询、课程/服务转化、品牌认知、评论互动 |

现有受众、组织方式、语气、页数和图片参数继续保留。

参数流转规则：

1. 新建创作时保存到大纲生成偏好。
2. 生成历史恢复时一并恢复。
3. 未填写的新字段使用自动推荐。
4. 用户在图片生成页单独修改布局、风格或比例时，覆盖对应推荐值。

## 4. 目录设计

### 4.1 页面布局

保留现有自动、封面、清单、步骤、对比、分类、关系、例子、总结，并增加：

- 强钩子封面
- 痛点—方案
- 误区—真相
- 前后对比
- 案例拆解
- 产品卖点
- 用户评价/证据
- FAQ 问答
- 数据结论
- 金句观点
- 章节分隔
- 行动号召页
- 口播字幕页
- 产品演示页
- 评论/聊天截图页

每种布局需要声明：

- 适用平台
- 适用获客目标
- 推荐内容字段
- 文字密度
- 推荐宽高比
- 样图资源
- 简短总结

### 4.2 图片风格

保留现有漫画、手绘、信息设计、东方绘画、材质插画、摄影与编辑分类，并增加：

- 品牌商业视觉
- 高级杂志编辑风
- UGC 生活方式
- 产品详情展示
- 电商销售海报
- 口播视频封面
- 评论/聊天截图风
- 3D 产品渲染
- SaaS/科技品牌风
- 高对比营销海报
- 清爽知识卡片
- 真实案例纪实风

每种风格需要声明：

- 风格总结
- 适合表达的内容
- 不适合的场景
- 适用平台
- 适用获客目标
- 推荐宽高比
- 文字密度
- 样图资源

样图要求：

- 优先使用清晰、主题匹配的本地资源。
- 卡片中使用裁剪缩略图，预览弹窗显示原图或更大尺寸。
- 样图缺失时显示“暂无样图”，不能静默显示空白区域。
- 自定义风格优先使用用户上传的参考图。

## 5. 推荐协议与优先级

推荐结果统一使用结构化对象：

```json
{
  "platform": "xiaohongshu",
  "goal": "product_conversion",
  "layout": "pain_solution",
  "image_style": "ugc_lifestyle",
  "aspect_ratio": "3:4",
  "content_structure": "hook_problem_solution_proof_cta",
  "reason": "适合通过真实体验和前后对比建立信任，并引导用户收藏或私信"
}
```

推荐优先级：

1. 用户明确选择。
2. 用户指定的平台和获客目标。
3. 主题、受众、语气和内容类型。
4. 目录元数据的匹配分。
5. 本地默认兜底。

冲突处理：

- 用户明确选择的单项只覆盖该单项。
- 平台和目标改变时，只重新计算仍处于自动状态的字段。
- 无法匹配时回退到通用多平台和现有默认风格。
- 推荐值必须通过当前启用目录校验。

推荐界面显示：

- 推荐的平台和目标
- 推荐布局
- 推荐风格
- 推荐比例
- 推荐理由
- 应用全部
- 只应用布局
- 只应用风格

## 6. 平台适配规则

### 小红书

默认偏向 3:4 或 4:3，优先考虑封面钩子、清单、痛点方案、避坑、前后对比、案例和收藏/评论引导。图片需要保留较强标题区和可扫描的信息层级。

### 抖音

默认偏向 9:16，优先考虑强钩子、口播字幕、产品演示、结果展示、评论/私信引导。重要文字应避开顶部、底部和右侧平台控件区域。

### 公众号

默认偏向 3:4、4:3 或由内容长度决定，优先考虑章节分隔、数据图解、案例分析、金句、FAQ 和总结行动页。长文页面允许更高文字密度，但必须维持清晰的段落层级。

### 通用多平台

优先选择文字和图片都容易裁剪的中性结构，避免强依赖某个平台控件位置的布局，并提示用户可以在生成后针对平台微调。

## 7. 文案与图片一致性检查

检查器以当前正文、页面标题、页面结构和图片生成提示词为输入，逐页输出：

- `consistent`：内容主体、结论和视觉重点一致。
- `mostly_consistent`：大体一致，但存在弱关联或表达范围扩大。
- `risk`：出现正文未提及的主体、数据、产品、结论或行动信息。

检查重点：

- 图片主题是否来自当前页面正文。
- 封面是否围绕标题和核心观点。
- 数据页是否只使用正文已有数据。
- 案例页是否只使用正文已有案例。
- 产品页是否出现正文未声明的产品属性。
- CTA 是否与获客目标一致。

结果需要给出页面编号、风险说明和建议，不自动修改正文或图片提示词。

## 8. 数据兼容与错误处理

- 新字段允许为空，空值等价于自动推荐。
- 旧记录读取不到平台和目标时使用自动推荐。
- 目录条目被禁用或删除时，推荐结果回退到可用的通用条目。
- 样图 URL 失效时显示错误占位，不影响选择和生成。
- 模型返回非法 JSON、未知 ID 或不完整字段时使用本地规则补齐。
- 任何推荐失败都不应阻塞用户手动生成。

## 9. 测试验收标准

### 后端

- 平台和获客目标可以保存、读取和恢复。
- 推荐协议兼容旧字段。
- 每个平台和主要目标至少有一组确定性兜底结果。
- 用户指定值不会被自动推荐覆盖。
- 未知布局、风格和比例会回退到可用值。
- 一致性检查能够识别正文外新增主体、数据和结论。

### 前端

- 大纲参数可选择平台和获客目标。
- 自动推荐状态有明确显示。
- 推荐理由和推荐组合可见。
- 布局和风格卡片可显示样图、缺图占位和放大预览。
- 选择单项不会意外覆盖其它用户选择。
- 旧历史记录仍可正常打开。

### 验收场景

1. 使用自动推荐生成一篇通用内容。
2. 使用“小红书 + 产品种草”生成内容，检查布局、比例和风格组合。
3. 使用“抖音 + 私信咨询”生成竖版内容，检查安全区和 CTA。
4. 使用“公众号 + 品牌认知”生成长文内容，检查章节和总结结构。
5. 手动指定布局和风格，确认推荐不会覆盖。
6. 删除或缺失样图，确认卡片有占位且预览不报错。
7. 检查一组正文与图片主题不一致的结果，确认能报告风险。

## 10. 实施顺序

1. 建立平台、获客目标和目录元数据模型。
2. 扩展布局和风格目录及样图资源。
3. 扩展后端推荐协议和本地兜底规则。
4. 接入大纲参数保存、恢复和前端选择器。
5. 接入推荐结果展示和单项应用操作。
6. 实现文案与图片一致性检查。
7. 完成后端、前端和关键流程测试。
