# 提示词目录、样图与多平台生成一致性设计

## 目标

梳理并修复单页布局、图片风格、发布平台和获客目标之间的职责边界，保证目录可理解、样图可预览、选项真正进入对应提示词，并让大纲、文案和图片生成保持一致。

## 背景与现状

当前系统已经具备：

- 单页布局目录，包含基础布局和面向增长场景的布局。
- 图片风格目录，覆盖摄影、插画、漫画、图解、3D 和商业视觉。
- 发布平台和获客目标选择。
- 自动推荐布局、风格、比例和内容结构。
- 图片风格进入图片提示词。
- 单页布局进入页面内容，并被图片服务转换为布局规则。

当前存在的问题：

1. 新增单页布局有目录名称和描述，但样图元数据、本地文件和前端展示可能不同步。
2. 单页布局混合了页面角色、信息结构、增长结构和媒体适配，用户难以判断选项差异。
3. 图片风格同时混合视觉媒介、视觉气质和商业用途，目录存在选择压力和语义重叠。
4. 发布平台和获客目标已经参与大纲生成与推荐，但没有明确贯穿文案和图片提示词。
5. 缺少统一的“最终生效设置”与提示词审计，无法确认每个选择是否真正发挥作用。

## 核心设计

### 1. 严格分离布局与风格

单页布局只描述：

- 信息区域
- 内容层级
- 阅读顺序
- 主体与文字的构图关系
- 对比、步骤、分类、关系等结构

图片风格只描述：

- 视觉媒介
- 材质和笔触
- 光影和色彩
- 视觉气质
- 适用场景

布局不能写成摄影、漫画、手绘等画风；风格不能写成封面、清单、对比等页面结构。

### 2. 三层选项模型

#### 内容层

- 大纲组织方式
- 目标受众
- 表达语气
- 页数
- 文案风格
- 正文结构
- 文案长度
- Emoji 丰富度

内容层影响“说什么、怎么组织、说多长”，进入大纲或文案提示词。

#### 视觉层

- 单页布局
- 图片风格
- 参考图角色
- 图片比例
- 分辨率、质量和输出格式

布局和风格分别进入图片提示词；图片参数继续通过接口参数传递。

#### 增长层

- 发布平台
- 获客目标

增长层不作为图片风格，而是作为跨模块约束，影响：

```text
发布平台 + 获客目标
→ 内容结构建议
→ 单页布局推荐
→ 图片风格推荐
→ 图片比例推荐
→ 行动号召建议
```

### 3. 布局目录分层

布局目录保留历史兼容 ID，同时增加明确分类：

- 页面角色：封面、内容页、总结页
- 信息结构：清单、步骤、对比、分类、关系、例子、问答、数据
- 增长结构：强钩子、痛点方案、案例证据、产品卖点、行动号召
- 媒体适配：口播字幕、产品演示、评论聊天

“封面”和“强钩子封面”不再被解释为完全同级的概念，而是可以理解为页面角色与增长结构的组合。

### 4. 图片风格目录分层

图片风格按以下维度整理：

- 视觉媒介：摄影、插画、漫画、手绘、3D、图解
- 视觉气质：极简、温暖、专业、复古、科技、活泼
- 商业用途：知识分享、产品展示、案例信任、营销转化

界面默认显示推荐、最近、全部和主要分类；详细筛选用于减少一次性展示 42 种风格带来的选择压力。

## 样图设计

### 布局样图

布局样图统一为本地排版示意图，不依赖临时外链，也不使用具体主题的真实案例图冒充布局示例。

每个内置布局至少包含：

```json
{
  "id": "hook-cover",
  "name": "强钩子封面",
  "category": "growth",
  "preview": "hook-cover",
  "preview_alt": "大标题占主要区域，主体图位于下方，底部保留行动区域",
  "summary": "用于首屏停留和主题切入"
}
```

样图只展示标题区、正文区、主体图区、标签区、编号区、对比区、行动区和阅读顺序，不展示具体业务文案，也不把内部提示词说明印到图片中。

前端必须：

1. 检查样图标识。
2. 检查本地文件是否存在。
3. 文件不存在时显示明确缺失状态。
4. 支持点击放大预览。

后端测试必须保证每个内置布局都有对应样图文件。

### 风格样图

风格样图只表达视觉媒介、材质、笔触、光影、色彩和气质，不承担页面排版说明。自定义风格可以使用用户参考图；没有可用样图时必须明确显示“暂无样图”。

## 统一生成上下文

生成前构造统一的 `GenerationContext`：

```text
GenerationContext
├── content
│   ├── organization
│   ├── audience
│   ├── tone
│   ├── page_count
│   ├── copy_style
│   ├── copy_structure
│   ├── copy_length
│   └── emoji_level
├── visual
│   ├── layout
│   ├── image_style
│   ├── aspect_ratio
│   └── reference_roles
└── growth
    ├── platform
    └── goal
```

最终生效设置和提示词审计信息需要保存到生成记录中，至少能回答：

- 用户选择了什么。
- 自动推荐选择了什么。
- 最终采用了什么。
- 哪些设置进入了大纲提示词。
- 哪些设置进入了文案提示词。
- 哪些设置进入了图片提示词。

## 提示词责任矩阵

| 选项 | 大纲提示词 | 文案提示词 | 图片提示词 |
|---|---:|---:|---:|
| 组织方式 | 直接使用 | 间接继承 | 不使用 |
| 目标受众 | 直接使用 | 直接使用 | 影响信息密度 |
| 表达语气 | 直接使用 | 直接使用 | 不使用 |
| 页数 | 直接约束 | 间接继承 | 间接继承 |
| 文案风格 | 推荐结果 | 直接使用 | 不使用 |
| 正文结构 | 推荐结果 | 直接使用 | 间接继承页面内容 |
| 文案长度 | 推荐结果 | 直接使用 | 不使用 |
| Emoji | 推荐结果 | 直接使用 | 不使用 |
| 单页布局 | 生成布局字段 | 间接继承 | 直接使用 |
| 图片风格 | 推荐结果 | 不使用 | 直接使用 |
| 参考图角色 | 识别参考信息 | 不使用 | 直接使用 |
| 图片比例 | 推荐结果 | 不使用 | 接口参数 |
| 发布平台 | 直接使用 | 直接使用 | 直接使用适配规则 |
| 获客目标 | 直接使用 | 直接使用 | 直接使用 CTA 和视觉重点 |

平台和目标进入提示词时转换为可执行规则，不机械地把字段名称作为图片文字。例如：

```text
发布平台：抖音
获客目标：涨粉关注

文案规则：
开头尽快给出冲突或结果，段落短，结尾自然引导关注。

图片规则：
突出一个核心标题，保留竖屏安全区，避免信息过密。
```

内部控制字段不得渲染到图片中。

## 一致性检查

增加目录和生成链路校验：

- 检查名称重复和相似。
- 检查布局描述是否混入画风。
- 检查风格描述是否混入排版。
- 检查样图与名称、描述是否一致。
- 检查平台和获客目标与布局、风格的适用元数据是否匹配。
- 检查所有已选项是否进入对应提示词。
- 检查平台和目标是否在大纲、文案、图片三个阶段保持一致。
- 检查自动推荐是否被用户手动选择正确覆盖。
- 检查图片文字是否来自正文，而不是控制参数。
- 检查文案与图片页面的主题、数字、主体、步骤和结论是否冲突。

## 兼容与错误处理

- 历史记录中的旧布局和旧风格继续可用。
- 旧提示词模板继续可用。
- 新规则只在模板支持时追加。
- 目录服务异常时使用本地内置目录。
- 样图缺失不阻塞生成，但显示明确原因。
- 选择已停用或无权使用的提示词时，阻止生成并要求重新选择。
- 手动选择始终优先于自动推荐。

## 验收标准

1. 所有内置布局都有可查看样图。
2. 所有内置风格都有正确样图，或明确标记暂无样图。
3. 新增布局不出现名称与样图不匹配。
4. 平台和获客目标能在大纲、文案、图片提示词审计中看到对应规则。
5. 手动选择会覆盖自动推荐。
6. 生成图片不会出现内部控制字段。
7. 用户可以查看最终使用的布局、风格、平台和获客目标。
8. 现有历史记录、旧提示词模板和旧目录 ID 不失效。
