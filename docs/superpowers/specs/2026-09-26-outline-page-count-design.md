# 大纲页数参数设计

## 目标

在大纲创作参数中增加页数选择。默认值为“自动”，保持现有自动判断策略；用户选择 1 至 15 页时，最终生成的大纲页数必须严格等于选择值。

## 用户规则

- 页数是最终大纲总页数，包含封面、内容页和总结页。
- `自动`：保持现有模型自动决定页数的行为。
- `1`：只生成封面。
- `2`：生成封面和总结页。
- `3` 至 `15`：生成封面、内容页和总结页，内容页数量为选择页数减 2。
- 选择固定页数时，不能因为模型输出偏差而返回其他页数。

## 交互设计

在现有“大纲偏好”参数区域增加“页数”下拉框：

- 选项顺序为“自动”、`1`、`2`、`3`……`15`。
- 默认值为“自动”。
- 生成过程中沿用现有禁用状态。
- 不改变现有组织方式、目标受众和表达语气参数。

## 技术设计

### 前端数据流

1. 在生成器状态中增加 `outlinePageCount`，类型为 `number | 'auto'`，默认值为 `'auto'`。
2. 在大纲参数组件中绑定下拉框。
3. 大纲请求将 `page_count` 传给 JSON 和 multipart 两种请求格式。
4. 大纲生成记录与本地草稿状态保存该参数，刷新或恢复草稿后仍能显示用户上次选择。
5. 生成成功后，固定页数模式校验响应页数；如果响应不符合要求，前端不保存不一致结果并提示重新生成。

### 后端数据流

1. 从 JSON 或 multipart 请求读取 `page_count`。
2. 统一校验值只能是 `auto`、空值或整数 `1` 至 `15`。
3. 将页数规则写入大纲提示词，明确要求：
   - 固定页数必须输出精确数量的页面；
   - 页面类型必须遵守 `1` 页封面、`2` 页封面加总结、`3` 至 `15` 页封面加内容页加总结；
   - `<page>` 分隔数量必须与选择值一致。
4. 在 `OutlineRun.preferences` 中保存规范化后的 `page_count`。
5. 大纲服务解析模型响应后，在固定页数模式执行服务端校验：
   - 页数不符时报错，不返回伪装成成功的结果；
   - 页数正确时继续返回结果；
   - 自动模式不增加新限制。
6. 预览接口使用同一套页数规范化和提示词规则，保证预览与实际生成一致。

## 错误处理

- 请求传入非法页数时，返回参数校验错误，不调用模型。
- 固定页数模式下模型返回页数不符时，返回明确错误：“模型未按指定页数生成，请重试”。
- 固定页数模式下页面类型不符合规则时，返回明确错误，避免后续图片生成使用错误结构。
- 自动模式沿用现有错误处理。

## 测试范围

### 后端

- 页数参数规范化接受 `auto` 和 `1` 至 `15`。
- 拒绝 `0`、`16`、小数、非数字字符串和未知字符串。
- 提示词包含固定页数规则。
- 固定页数 1、2、5、15 的解析校验。
- 固定页数下错误页数返回失败。
- `OutlineRun.preferences.page_count` 保存规范化值。
- 预览接口和正式生成接口使用同一页数规则。

### 前端

- 页数选择器默认显示“自动”，并提供 1 至 15。
- 生成请求携带 `page_count`。
- 草稿保存和恢复保留页数选择。
- 固定页数响应不符合要求时不覆盖已有大纲并显示错误。

## 非目标

- 不修改文案生成接口的页数逻辑。
- 不改变自动模式当前的页数策略。
- 不增加自定义页数输入框。
- 不对已经生成的历史大纲重新拆分或补页。
