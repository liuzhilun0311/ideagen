# 图片分析与参考资产复用设计

**日期：** 2026-09-26  
**状态：** 已确认，待实施

## 1. 目标

为 IdeaGen 增加统一的图片分析能力：

- 输入图片后，使用现有文本服务商的多模态能力解析图片内容。
- 将分析结果拆分为内容、单页布局、图片风格三个部分。
- 内容可保存为参考素材，布局和图片风格可保存到提示词库。
- 首页、工作台、提示词中心都能进入同一套分析能力。
- 分析结果可以直接使用，也可以编辑后再使用。
- 应用到已有创作时默认合并，不覆盖用户当前内容。

第一版不新增独立图片理解模型配置，直接复用现有文本模型配置和多模态请求能力。

## 2. 产品边界

图片分析结果不作为一个混合提示词直接保存，而是拆成三个职责明确的部分：

| 部分 | 主要用途 | 持久化位置 |
| --- | --- | --- |
| 内容 | 当前创作、内容改写、参考资料复用 | 参考素材库 |
| 单页布局 | 当前页面布局约束、后续页面复用 | 提示词中心的图片布局分类 |
| 图片风格 | 当前页面或整套创作的视觉风格 | 提示词中心的图片风格分类 |

原始分析记录独立保存，用于回看、编辑、重新拆分和再次保存。它不直接等同于提示词条目或参考素材。

### 2.1 原图保存策略

- 首页和工作台：保存为参考素材时可以保留原始图片。
- 提示词中心：从分析结果创建布局或风格提示词时不保存原图。
- 参考素材库：保存原图、结构化分析、改写内容和用户备注。
- 用户可以编辑或删除参考素材中的原图。

### 2.2 暂不支持

- 多张图片批量归纳。
- 图片相似度搜索或 embedding。
- 自动生成完整多页作品。
- 独立图片理解模型配置。
- 公开素材市场。
- 将图片分析直接发布为新的复合模板类型。

## 3. 用户流程

统一流程如下：

```text
进入图片分析
  -> 上传图片
  -> 调用现有文本模型分析
  -> 展示内容 / 单页布局 / 图片风格
  -> 分别编辑、应用或保存
```

### 3.1 首页

首页的分析结果用于新作品：

- 内容可以追加到参考内容或保存为参考素材。
- 单页布局可以作为后续页面生成的补充约束。
- 图片风格可以作为本次创作的风格补充。
- 不直接替换用户已经填写的主题、参考内容或默认设置。

### 3.2 工作台

工作台的分析结果服务当前选中的页面：

- 内容追加到当前页面的参考信息。
- 单页布局追加到当前页面布局要求。
- 图片风格追加到当前页面的风格说明。
- 默认使用合并模式。
- 用户可以显式选择替换当前对应字段。
- 应用后由现有保存流程保存到作品。
- 作品需要保存实际应用过的分析快照，不能依赖后续提示词目录反推。

### 3.3 提示词中心

提示词中心提供“从图片创建提示词”入口：

- 用户上传图片并查看分析结果。
- 只允许勾选单页布局和图片风格进行保存。
- 内容部分不能直接写入提示词库。
- 保存前可编辑名称、描述和提示词正文。
- 保存结果沿用现有提示词中心的权限、版本、共享、复制和排序机制。
- 原图不进入提示词条目。

### 3.4 参考素材库

参考素材库保存：

- 原始参考图片。
- 结构化内容分析。
- 可直接使用的改写内容。
- 用户备注。

素材可在首页和工作台重新打开、编辑、追加到创作上下文或再次分析。

## 4. 分析结果设计

### 4.1 统一分析记录

建议新增 `reference_assets` Django app，并在其中保存图片分析记录与参考素材。

分析记录包含：

```text
ImageAnalysis
├── id
├── owner
├── source_image_path       可选，提示词中心创建提示词时可为空
├── source_image_digest
├── content
├── layout
├── visual_style
├── rewritten_content
├── user_note
├── status
├── created_at
└── updated_at
```

分析记录是用户私有对象，默认不共享。

### 4.2 内容结构

```json
{
  "summary": "图片表达的主题与核心信息",
  "subjects": ["主要主体"],
  "text_structure": [
    {
      "role": "title",
      "text": "识别到的标题或标题特征"
    }
  ],
  "visual_focus": "视觉主体和重点",
  "rewrite": "可直接用于新创作的改写内容"
}
```

实际 OCR 文本只作为识别结果，不承诺逐字准确。界面必须允许用户编辑后再使用。

### 4.3 单页布局结构

```json
{
  "page_type": "cover",
  "description": "整体版式描述",
  "regions": [
    {
      "role": "title",
      "position": "top",
      "size": "large",
      "description": "标题区域特征"
    }
  ],
  "hierarchy": "标题优先，主体居中，辅助信息位于底部",
  "spacing": "四周保留明显安全边距",
  "prompt_text": "可复用的单页布局提示词"
}
```

### 4.4 图片风格结构

```json
{
  "description": "整体视觉风格描述",
  "attributes": [
    "柔和低饱和配色",
    "纸张纹理",
    "手绘线稿",
    "自然光"
  ],
  "palette": ["主色", "辅助色"],
  "medium": "illustration",
  "lighting": "soft natural light",
  "composition": "简洁、留白充足",
  "prompt_text": "可复用的图片风格提示词"
}
```

图片风格提示词只描述视觉表现，不写死分辨率、宽高比、质量和输出格式。图片参数继续由现有参数层控制。

## 5. 与现有系统的连接

### 5.1 生成模块

分析调用放在 `generation` 模块中，复用现有文本客户端：

- OpenAI-compatible 多模态协议继续使用现有 `text_client` 或相应协议客户端。
- Google GenAI 使用现有图片输入能力。
- 生成前执行用户服务商权限和配置校验。
- 分析请求不调用图片生成服务商。

后端必须校验模型返回的 JSON，缺失字段使用安全默认值，格式错误返回结构化错误，不创建半成品记录。

### 5.2 提示词中心

布局和风格保存通过现有提示词目录流程进入 `PromptEntry`：

- 布局使用 `module=image`、`category=layout`。
- 风格使用 `module=image`、`category=style`。
- 保存前生成可编辑草稿。
- 不接受客户端直接提交未授权的完整提示词正文来绕过目录校验。
- 生成时仍由服务端按当前用户解析并冻结目录版本。

### 5.3 工作台状态

前端使用现有 `generator` Store 和 `studioSession`：

- 分析结果初始只作为临时状态。
- 用户点击应用后写入当前作品状态。
- 内容写入参考内容或页面参考字段。
- 布局写入页面布局偏好或页面内容中的结构化布局字段。
- 风格写入当前图片风格的补充说明。
- 合并应用不得清除原有值。
- 作品保存时保存应用结果的快照。

如现有页面模型缺少页面级参考字段，应增加明确的结构化字段，不将全部信息拼接成不可逆的自由文本。

## 6. API 设计

### 6.1 分析

```text
POST /api/image-analysis
```

请求支持 `multipart/form-data`，至少包含一张图片，可选主题或当前页面上下文。

返回：

```json
{
  "success": true,
  "analysis": {
    "id": "analysis-id",
    "content": {},
    "layout": {},
    "visual_style": {},
    "rewritten_content": "",
    "source_image_available": true
  }
}
```

未保存分析也可以返回临时结果，但只有明确保存或创建提示词后才持久化为用户资产。

### 6.2 分析结果编辑与应用

```text
GET /api/image-analysis/<id>
PUT /api/image-analysis/<id>
POST /api/image-analysis/<id>/apply
DELETE /api/image-analysis/<id>
```

`apply` 请求包含：

```json
{
  "target": "home|workspace",
  "parts": ["content", "layout", "visual_style"],
  "mode": "merge|replace"
}
```

服务端只返回规范化后的应用数据，不直接修改未指定的作品状态。

### 6.3 参考素材

```text
GET /api/reference-assets
POST /api/reference-assets
PUT /api/reference-assets/<id>
DELETE /api/reference-assets/<id>
```

参考素材创建时可以关联分析记录，并选择是否保存原始图片。

### 6.4 从分析创建提示词

```text
POST /api/prompt-center/from-analysis
```

请求：

```json
{
  "analysis_id": "analysis-id",
  "parts": ["layout", "visual_style"],
  "names": {
    "layout": "我的卡片布局",
    "visual_style": "柔和手绘风"
  },
  "drafts": {
    "layout": {},
    "visual_style": {}
  }
}
```

该接口必须复用提示词中心的占位符、权限、版本和名称校验。

## 7. 权限与安全

- 所有分析、素材和应用接口必须认证。
- 分析记录与参考素材只能由拥有者访问，除非未来明确增加共享能力。
- 图片文件按用户目录隔离，并使用安全文件名、路径 containment 和 MIME 校验。
- 日志不得记录图片二进制、API Key 或完整敏感请求内容。
- 原图和素材删除时删除对应文件，但不影响已经生成的历史作品。
- 历史作品保存分析快照，不依赖当前素材或提示词是否仍存在。
- 模型返回的文本不能直接作为 HTML 渲染，前端需要进行普通文本转义。

## 8. 错误处理

以下情况返回现有结构化 API 错误：

- 图片缺失、格式不支持或超过大小限制。
- 当前用户没有可用的多模态文本模型。
- 服务商认证失败、接口超时或上游拒绝。
- 模型返回无法解析的 JSON。
- 分析结果字段不完整或超出约束。
- 访问其他用户的分析记录或参考素材。

错误时：

- 不创建半成品提示词或参考素材。
- 不改变当前创作状态。
- 前端保留当前编辑内容。
- 提供重新分析入口。

## 9. 前端交互与视觉要求

- 三类结果使用独立分区，不能只用颜色区分。
- 每个分区有独立的编辑、应用和保存操作。
- 主要按钮遵循当前工作台层级，避免出现多个同等级主 CTA。
- 保存提示词使用现有提示词中心表单和命名规范。
- 应用到当前创作时显示“已合并”状态和可撤销提示。
- 分析中保持稳定布局，显示上传、识别和失败状态。
- 移动端使用纵向分区，避免结果卡片造成横向滚动。
- 原图预览只在首页、工作台和参考素材库显示；提示词条目不显示原图。

## 10. 测试与验收

### 后端

- 多模态客户端调用和图片输入协议测试。
- 结构化 JSON 成功、缺字段和格式错误测试。
- 分析记录的创建、编辑、删除和用户隔离测试。
- 参考素材原图保存与删除测试。
- 从分析创建布局/风格提示词的分类、权限、版本和名称冲突测试。
- 失效提示词、无权限资源和文件路径穿越测试。
- 历史作品中的分析快照不受后续资产删除影响。

### 前端

- 首页、工作台、提示词中心三个入口都能打开分析流程。
- 内容、布局、风格可分别应用和保存。
- 默认合并不会覆盖已有主题、参考内容、布局和风格。
- 替换模式只影响用户明确选择的部分。
- 取消、失败和重新分析不会污染当前工作台状态。
- 参考素材库可以重新打开和编辑分析结果。
- 类型检查、单元测试和生产构建通过。

### 验收标准

1. 上传图片后能返回内容、单页布局和图片风格三类结构化结果。
2. 三类结果可分别编辑、应用和保存。
3. 内容只能进入参考素材库，不自动进入提示词库。
4. 布局和图片风格可以保存为现有提示词目录条目。
5. 首页、工作台、提示词中心共用同一套分析后端能力。
6. 应用到已有创作时默认合并，不破坏原有输入。
7. 历史作品保存实际使用过的分析快照。
8. 用户之间的分析记录、原图和参考素材相互隔离。
9. 分析失败不会生成半成品资产，也不会污染当前创作。
10. 现有生成、历史、提示词和图片后处理流程保持兼容。
