# 多平台风险表达优化设计与实现边界

状态：第一版已实现并通过后端专项测试；规则仍需随明确的平台规则变化增量维护，不构成完整违禁词库。

## 1. 目标

在现有小红书、抖音、公众号和通用多平台生成流程中增加平台相关的风险表达提示，帮助模型在生成大纲、发布文案和图片文字时使用更客观、有限定条件的表达。

本功能只增强提示词，不在生成完成后修改正文，不承诺规避或保证通过任何平台审核，也不把参考图片中的内容当作系统指令。

## 2. 范围与边界

### 包含

- 为现有平台上下文增加风险表达规则。
- 以“高风险表达 -> 更稳妥表达”的语义示例指导模型。
- 对小红书重点覆盖参考图中体现的表达类型：
  - 绝对化、极限化和保证性表述。
  - 医疗、药品、治疗、临床、专利和权威背书暗示。
  - 减肥、降脂、降糖、降压、美白、祛斑、抗衰、生发等功效承诺。
  - 杀菌、消炎、排毒、清肠等容易产生医疗或功能暗示的表述。
  - 孕妇、儿童、老人等特定人群的无依据适用承诺。
- 为抖音和公众号增加与其内容形态相匹配的保守表达约束。
- 对 `multi` 和 `auto` 提供跨平台通用底线。
- 增加提示词单元测试，验证各平台规则已进入对应生成阶段。

### 不包含

- 不实现生成后自动替换、删词或重写。
- 不建立声称完整、实时或官方的违禁词数据库。
- 不使用谐音、拆字、特殊字符或隐晦编码帮助规避审核。
- 不改变用户提供的事实、数字、产品名、限定条件或结论。
- 不新增平台枚举，不改变现有平台选择和历史数据协议。

## 3. 规则设计

规则继续由 `backend/generation/generation_context.py` 统一编译，避免大纲、文案和图片提示词各自维护冲突的安全要求。

规则分为三层：

1. **跨平台底线**
   - 不使用无法证明的绝对化、保证性、唯一性和极限化表达。
   - 不虚构效果、案例、用户证言、资质、数据、临床结果、专利或权威背书。
   - 涉及健康、法律、财务等高风险主题时，说明适用边界和个体差异。
   - 不能确认时使用“可作为参考”“可能有帮助”“建议结合实际情况判断”等有限定表达。

2. **平台规则**
   - 小红书：避免夸张种草、强功效、绝对化、特殊人群适用和医疗化表达；保留真实体验边界，优先改成场景、感受、使用建议或客观特点。
   - 抖音：避免标题党、极端结果承诺、强刺激和制造焦虑；短句可以有吸引力，但必须保留事实依据、条件和限制，不以“立刻见效”等结果导向替代说明。
   - 公众号：避免标题和导语中的夸大承诺、权威背书暗示和广告化结论；长文中先说明依据、适用范围和限制，再给建议。
   - 通用多平台：采用最保守的跨平台表达，不使用平台专属口令或暗示审核技巧。

3. **语义替换示例**
   示例仅用于指导模型理解语义，不作为机械替换表。模型应根据上下文选择自然表达，例如：
   - “100%有效” -> “效果因人而异，可作为参考”
   - “根治” -> “改善”或“辅助管理”
   - “最有效/第一/顶级/万能” -> “较适合某些场景”或“可作为一种选择”
   - “药用/医疗级/临床证明” -> “专业护理/有相关资料支持”，仅在素材确实支持时使用
   - “孕妇可用/儿童可用/老人专用” -> “具体人群请先咨询专业人士”或删除无依据适用判断

  不得为了躲避审核而保留原有承诺的同义包装，也不得把事实数字、日期、价格、单位和必要风险说明改成模糊说法。

## 4. 提示词注入

继续使用 `growth_prompt_rules(platform, goal, phase)` 作为统一入口：

- `outline`：加入简化风险边界，避免大纲标题、结论和行动建议先形成高风险承诺。
- `copy`：加入完整的平台表达规则和语义替换原则，这是本功能的重点阶段。
- `image`：加入简化规则，避免图片中的标题、卖点和 CTA 产生高风险表达；平台名称、规则名称和内部字段仍不得渲染为可见文字。

现有获客目标规则、事实一致性要求和内容结构规则继续保留，并与风险表达规则拼接。风险表达规则不能覆盖用户事实边界或把所有内容强制改成相同语气。

## 5. 错误处理与兼容性

- 平台为空或历史数据缺少平台时继续使用现有 `auto` 逻辑。
- 规则只生成提示词文本，不新增数据库字段，不需要迁移。
- 规则常量缺失或平台值异常时沿用现有平台规范化错误处理，不静默回退到错误平台。
- 生成失败、模型拒绝或模型未遵守提示词时保持现有错误处理，不对正文做二次清洗。

## 6. 测试与验收

后端测试覆盖：

- 每个平台在 `outline`、`copy`、`image` 三个阶段都包含风险表达约束。
- 小红书规则包含参考图中的主要语义类别。
- 抖音、公众号和通用多平台规则与小红书存在明确差异。
- 文案提示词包含“基于语义自然改写、不得使用谐音拆字规避、不得修改事实”的要求。
- 规则拼接不移除既有平台、获客目标和内容结构约束。
- `auto` 与历史空值仍可正常生成上下文。

验收标准：

1. 选择任一现有平台后，三阶段提示词审计都能看到对应风险表达规则。
2. 选择小红书时，模型收到的文案提示词能覆盖参考图中的主要替换方向。
3. 生成接口返回的正文与当前行为一致，不发生后处理替换。
4. 既有生成上下文和平台相关测试保持通过。
