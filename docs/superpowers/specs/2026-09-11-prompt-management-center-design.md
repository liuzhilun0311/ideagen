# 提示词管理中心

日期：2026-09-11

## 目标与范围

让管理员和用户通过提示词模块维护基础规则和创作选项。
创作页面继续只选择组织方式、受众、语气、布局、风格、结构和长度，
不恢复整套提示词模板选择。管理页面与所有生成、重试和预览路径必须使用同一份目录。

## 分类

| 生成模块 | 分类 |
| --- | --- |
| 大纲 | 基础规则、组织方式、目标受众、表达语气 |
| 图片 | 基础规则、单页布局、图片风格 |
| 文案 | 基础规则、文案风格、正文结构、文案长度 |

一个选项仅属于一个模块和分类。创建时确定分类，发布后不得跨类移动；
需要不同用途时复制成新条目。图片参数不属于提示词分类，继续以接口参数为准。
自动选择与自定义受众输入作为系统行为保留，用户不能创建同名条目冒充这些行为。

每个模块仅有一份当前生效的基础规则，不提供多份基础规则同时选择或叠加。
基础规则编辑限管理员，历史版本和恢复默认可用。

## 条目与数据

使用数据库持久化条目和版本，而非修改源代码中的常量或发布包里的文件。
沿用项目已有数据库与备份、Docker数据卷，不新增外部服务。

条目包含稳定编号、模块、分类、名称、场景说明、指令正文、拥有者、
启用状态、共享范围、指定用户、当前版本和修改时间。
图片风格另有可选的颜色与风格分组；新增风格无样图时用明确占位，
不伪造效果示例。已有风格样图继续使用。

同一拥有者在同一分类内不得有重复名称；不同拥有者的同名选项显示来源，
实际选择以编号区分。修改名称不会改变编号。
用户排序复用现有排序机制，每个用户、模块和分类独立保存，不改变他人排序。

## 权限

所有接口必须认证，服务端执行权限判断，不能只过滤前端选项。

| 操作 | 拥有者 | 被共享用户 | 管理员 |
| --- | --- | --- | --- |
| 查看、使用已启用条目 | 是 | 是 | 是 |
| 编辑、停用自己的条目 | 是 | 否 | 是 |
| 复制可见条目为自己的新条目 | 是 | 是 | 是 |
| 编辑或恢复系统基础规则 | 否 | 否 | 是 |
| 设为所有用户可用 | 否 | 否 | 是 |
| 设置自己条目的指定用户 | 是 | 否 | 是 |

普通用户不能通过共享接口转授他人条目的权限。
共享范围为仅自己、指定用户、所有用户；最后一项仅管理员可选。
指定名单使用用户编号，提交时验证目标用户存在，防止改名造成授权丢失。
用户选择器只返回授权配置所需的编号和用户名，不暴露账号其他字段。
管理员操作他人条目时保留原拥有者，记录操作者。

被共享用户可以查看用于选择的当前指令并复制。
条目的完整管理历史仅拥有者和管理员可见。
撤销授权后不得继续新生成，但不影响已经生成的作品或有权访问的作品请求快照。

## 管理界面

顶部为生成大纲、生成图片、生成文案三个标签。
每个模块内按分类筛选，另设旧版模板入口，默认不混入新目录。
列表显示名称、场景、状态、来源、可用范围和更新时间，支持搜索。
选项提供新增、编辑、复制、排序、停用、配置用户和版本记录。
基础规则固定展示，不可删除、拖动或停用。
编辑器展示正文和字符数，提示词占位符使用受控白名单。
颜色用色板，启停用开关，排序使用现有拖拽及上下移动控件；
在手机上保留上下移动操作，不能只依赖拖拽。
离开未保存的编辑时确认，不丢弃输入；提交期间禁止重复操作。

复制后获得新的编号，名称自动去重，默认仅自己可用，不继承原条目的授权名单。
新条目放在当前分类中，复制项放在源条目下方，便于继续编辑。

## 版本与保存

每次修改内容、名称、场景、状态或授权记录操作者和新版本。
编辑、排序、恢复携带读取时的版本号；发生并发修改返回冲突，
提示重新加载，不用旧表单覆盖别人的新修改。
恢复旧版本复制其内容为一个新版本，不抹除历史。
恢复正文时不恢复旧授权，避免无意重新开放权限。
内置默认文本独立保留；恢复默认须确认，并记录为新版本。

默认提供停用而非硬删除。旧条目和版本保留，供历史作品追溯。
基础规则保存时验证必要占位符；输出结构协议由程序统一追加，
不得依赖用户可编辑文本维持解析契约。

## 与生成的连接

选项目录接口返回当前用户能使用的条目以及可编辑能力。
管理页面负责管理，创作页面只展示可选条目。
管理保存后刷新目录；进入或重新激活创作页面也刷新目录。
正在编辑的作品保存所选编号及最后已知名称，不把编辑后的指令写死在前端。

服务端在每次预览、生成时按当前用户检查编号、模块、分类、启用状态和权限。
默认选项与显式选择区分处理：

- 缺少旧作品选项时使用对应系统默认。
- 显式选择的条目不存在、停用或失去授权时，保留旧名称并提示重新选择。
- 不得把失效选择悄悄替换成另一种风格，也不得直接相信客户端提交的正文。
- 自动推荐只从用户可使用的启用图片风格中选择。

一次生成开始前解析全部基础规则和选项，冻结文本、编号和版本。
进行中的同一批图片不会因为管理员修改配置而混用新版本。
图片单页生成、剩余页面生成、重试、重新生成和候选版本生成都接入该解析流程。
基础规则只保留共性指令，各选项仅包含差异，避免叠加重复的风格或长度要求。
文案受众继承时仍按受众分类校验；显式文案风格覆盖大纲口吻，但不能改变事实。

## 预览与快照

管理页可填示例主题、内容及选项，预览完整组合。
创作页继续提供真实当前输入的提示词预览。
两者都调用实际生成使用的组合模块，预览不保存作品、不调用模型。
管理员预览未保存文本是临时草稿预览，必须明确区别于当前生效配置。

生成请求记录实际组合后的正文、所用条目编号和版本以及有效参数，
不记录密钥；图片二进制不混进提示词正文。
已有大纲记录和图片诊断复用，补足文案请求记录。
历史快照不因当前条目改名、编辑、停用、撤销共享而变动。
请求快照按作品权限读取，不通过条目详情接口绕过授权。
旧生成缺少快照时明确显示未记录，不能用今天的配置反推冒充旧请求。

在预览后配置被修改时，生成前检测版本变化，要求刷新预览或确认使用最新版本。
客户端不得提交旧正文绕过停用和撤权。

## 迁移与兼容

首次迁移将当前三类基础文本、已有图片风格与各类选项导入数据库。
当前管理员已修改的基础文本优先保留，不盲目覆盖为仓库默认值。
导入幂等，重跑启动或升级不能覆盖管理页面已修改的内容。
现有中文选项值和风格编号建立内置映射，旧作品保持原选择。
旧用户完整模板仍保留在旧版模板，继续保留拥有者与授权，
不自动拆成风格，也不自动参与新生成。
数据库迁移前按现有项目方式备份。不要删除作品或重建用户数据。

## 验证

1. 普通用户、拥有者、共享用户、管理员的接口权限矩阵测试。
2. 新增、复制、重命名、停用、授权、恢复版本与并发冲突测试。
3. 所有生成路径拒绝失效或越权选项；目录过滤不能代替调用校验。
4. 大纲、单页图片、图片批量、文案预览与实际请求使用同一版本快照。
5. 旧作品映射、重复迁移、重启持久化与旧模板保留测试。
6. 修改基础规则不会破坏JSON或大纲解析协议；占位符非法时返回可理解错误。
7. 管理端改名后创作端正常选择；新选项对授权用户可见，对未授权用户不可见。
8. 桌面和手机完整操作检查，拖拽与移动按钮均可用。
9. 现有前后端测试、类型检查、生产构建通过。
10. 验证使用模拟模型客户端，不产生付费调用；不承诺真实生成效果必然符合风格。

## 实施边界

不增加真实付费试生成、团队角色体系、审核发布流程或提示词市场。
不改模型配置、计费、作品下载功能。
先实现目录、版本和权限，再连接三类生成，最后切换管理界面与迁移。
只有三个生成模块实际消费新配置并完成验证后，才能声称管理中心完成。
