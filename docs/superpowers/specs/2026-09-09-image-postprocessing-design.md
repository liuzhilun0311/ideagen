# 图片后处理与版本使用设计

日期：2026-09-09

状态：交互方向已获用户确认；本文待用户复核，尚未实施。

## 目标

把现有“去AI化”从下载流程迁移至图片制作流程。用户无需下载即可查看、复制和使用处理后的图片；原图始终保留。图片制作、发布文案、作品预览和作品列表共享已持久化的版本选择，不互相限制导航。

## 现状与边界

- `frontend/src/composables/useDeaiDownload.ts` 在导出时调用批处理。
- `backend/providers/views.py` 的 `run_deai` 同步处理整个任务目录，执行前删除旧输出目录，没有逐页持久化状态，不适合作为新版本系统直接复用。
- `frontend/src/stores/generator.ts` 每页只有一个图片 URL，历史数据也尚无处理版本信息。
- 现有脚本使用噪点、色彩、锐化和缩放等后处理；本功能不承诺规避 AI 检测，不表示图片来源改变，也不自动调用新的图片模型。
- 原文件不得被处理脚本原地修改；采用隔离输入副本和独立输出目录。
- 本轮不继续排查模型供应商权限，不进行真实付费模型调用。

## 用户流程

### 查看与采用

图片展示区提供“原图 / 处理图 / 对比”。桌面端对比为同尺寸并排，移动端以切换查看为主。查看版本与采用版本分离：切换对比不会改变作品使用的图片。

每页明确显示“当前采用：原图”或“当前采用：处理图 · 轻度/中度/重度”，允许主动切换采用版本。放大、复制和单张保存作用于正在查看的具体版本；对比状态下分别提供对应版本操作，避免目标含糊。

作品预览、作品列表缩略图和默认整套导出使用每页当前采用版本。处理完成后默认采用新处理图。若任务开始后用户主动改变采用版本，则后台完成不得覆盖该主动选择。

### 单张处理

图片工具栏提供强度选择和“处理当前图片”；已有结果显示“重新处理”。首次默认轻度，保护图中文字清晰度；保留用户后续偏好。改变强度只修改下一次处理参数，不立即启动处理，不改变已有结果标注。

每次都从对应原图版本开始处理。成功后发布完整结果；失败保留原图及此前成功处理图。只保留一个当前处理结果，不实现无限版本历史。

### 批量处理

整套图片操作区提供批量强度和“全部去AI化”，标注待处理数量；生成设置与下载页不重复放置这些执行按钮。

默认跳过已有有效结果和正在排队/处理的图片，保留单张精调。明确的“按此强度重新处理全部”需确认后提交，旧结果在新结果成功前仍然可用。失败页可独立重试，也可批量重试失败项。

批处理采用提交时的图片集合与强度快照；之后修改选择不影响运行中任务。未生成成功的图片不进入手动批处理。

### 自动处理

提供“生成后自动去AI化”开关，首次关闭，记住用户选择和自动处理强度。每张图片生成成功后由服务器排队，不等待整套图片生成结束。

开关只影响之后生成成功的图片；打开时不追溯处理既有图片，已有图片使用批量按钮。关闭不取消已提交任务。单张重新生成同样遵循自动处理设置。

### 状态和导航

每页独立显示未处理、排队中、处理中、已处理（含实际强度）、处理失败。批量显示完成数、失败数和总数。生成状态与处理状态分开，后处理失败不得显示为模型生成失败。

后台任务不依赖浏览器页面持续打开。切换模块、刷新、退出再登录以及同账号换设备后，均从服务器恢复状态。失败不阻止其他页使用；不自动无限重试。

## 数据与服务边界

后处理使用独立服务和任务记录，不再堆入供应商配置视图。模型生成仅负责发布原图及触发可选任务；后处理服务负责排队、转换和持久化；前端负责状态展示和版本选择；导出服务只读取既有版本。

每页绑定稳定页面标识、原图修订标识和内容摘要。处理记录包含所有者、作品、页面、源版本、强度、算法版本、状态、错误摘要、输出路径和时间。采用版本记录单独维护。

后端提供提交单张/批量任务、查询状态、选择采用版本与鉴权取图的能力。请求使用作品和页面标识，不接受任意文件路径或任意远程 URL。

任务状态持久化数据库，由独立 worker 消费；Docker 部署中 worker 与 Web 共享数据库和持久化图片卷。数据库驱动队列初版不引入 Redis；跨进程领取必须原子化。worker 中断通过租约回收恢复，设置有限重试次数，避免永久停留在处理中。

相同源版本、强度及算法版本的有效结果可以复用，重复点击不得创建并行重复处理。输出先写临时文件并验证可解码，再原子发布。重新处理不先删除有效结果。

所有任务查询、版本选择与图片读取必须验证作品访问权限，不能仅凭 task_id 推断目录所有者。路径限定在允许的数据目录内；密钥、内部绝对路径和原始进程输出不得暴露给客户端。

## 版本失效与兼容

原图重新生成后，旧处理结果不得附着到新图。运行中任务完成时须核对源修订，不匹配则不发布到当前页，也不覆盖采用选择。

页面删除、重新排序和切换作品不得造成结果串页。旧作品默认采用原图；旧处理目录没有可信源版本信息时不自动认定为有效结果，用户可重新处理。

服务端持久化结果、实际强度和采用选择，前端本地缓存不是事实来源。访问令牌不作为图片版本标识，不存入结果元数据。

## 下载与直接使用

移除下载触发处理、生成本地处理 bat 和要求用户配置脚本的流程。下载入口改为“下载作品”，默认导出当前采用版本，可明确选择原图或处理图。

显式导出处理图但存在缺失时，应提示缺失页并让用户选择返回处理或仅导出已完成页，不静默混入原图。默认当前采用版本导出可混合原图与处理图，但必须与预览一致。

浏览器复制/分享不可用时提供明确反馈和保存替代入口，不宣称所有手机都可直接写入相册或分享到任意应用。图片查看本身不依赖文件夹选择 API。

## 验收

- 单张及批量处理成功后，无需下载即可看到处理图并使用正确版本。
- 原图字节在处理前后保持一致；修改强度后仍从原图处理。
- 对比不改变采用选择；预览、缩略图与默认导出遵循同一采用规则。
- 已有结果在重新处理失败后仍可用；部分失败不影响其他页面。
- 重复提交、切换页面、切换作品、源图更新和任务晚到不导致串图或覆盖主动选择。
- 自动处理按页触发；关掉页面后仍执行；worker 重启后能恢复可恢复任务。
- 同账号跨设备恢复版本，不同账号无法读取或处理对方作品。
- 桌面与 390px 手机宽度验证布局、图片切换、按钮点击及长状态文本。
- 用合成图片验证后端真实后处理，用模拟生成验证自动衔接；不调用付费模型。
- 前后端回归测试、类型检查、构建及 Docker worker 持久化验证完成后才能声明交付。
