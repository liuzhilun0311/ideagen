# Recommendation Visibility Verification

## Root Cause

The home page passed `showGrowth=false` to OutlineOptions, hiding both
platform controls and the recommendation. In the image workspace the same
recommendation lived inside outline-adjustments, which the active toolbar
layout hides with CSS. The presence of RecommendationSummary did not establish
that users could see or operate it.

## Changes

- Extracted a standalone OutlineRecommendation used below the home heading and
  below the image workspace navigation, outside hidden panels and disclosures.
- Displayed platform, goal, layout, image style, aspect ratio, content structure,
  and the recommendation reason.
- Kept an explicit empty state for legacy outlines without recommendation data.
- Preserved manual selections, including layouts stored only in legacy page text.
- Kept apply-all, layout-only, and style-only actions; added busy-state guards,
  local persistence and visible applied/no-change feedback.
- Existing generated images are not automatically regenerated by these actions.
- Updated preview fixtures to include the actual recommendation response contract.

## Boundaries

No paid upstream model call was made. These checks verify frontend visibility,
interaction, state propagation, and the mock response flow, not actual model
recommendation quality. Missing historical recommendations are not invented.
Content structure and reason are descriptive recommendation fields, not a
request to silently regenerate an existing outline.
